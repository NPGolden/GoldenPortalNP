# GAS-CP-R68-001 — security review (customer app 1.0.0), 31/10/2026

Continues CS-28 … CS-35 (R66-001). All measures are performance-neutral: the customer app reuses the existing module, adds no query to portal pages and writes only through the portal's own functions.

| # | Measure | Where |
|---|---|---|
| CS-36 | **Customer accounts only.** `api_act_as()` and `Portal::login()` gate per app: `X-App: customer` requires role `customer` with a customer_id; staff tokens are refused at sign-in and at every request (`PortalCustomer::allowed`). Conversely a customer token never reaches a staff route: everything outside `/cu/*` except `/me`, `/auth/logout`, `/devices/push-token` returns 403. | bootstrap.php, lib/portal.php, index.php |
| CS-37 | **Customer scope by the portal, not by the app.** Every read uses `scope_sql()` / `tk_scope()` (customer_id), drafts hidden, `visibility = external` for files and ticket comments; file streams go through `cp_stream_file()` / `tk_stream_file()` which re-check the customer. No endpoint takes a customer_id from the client. | lib/portal_customer.php |
| CS-38 | **No internal data.** Ticket internal notes (`visibility = internal`) are filtered by `tk_load()` for non-staff and double-checked in the shape; offers carry amount and VAT (what the customer sees on the web) and never cost / margin / notes; documents exclude `fsr_sign`, `offer_sign`, proformas, accounting and bank-guarantee files and any `offer*` kind. | lib/portal_customer.php |
| CS-39 | **Legally relevant actions.** Accept report / approve document / accept or reject offer require the acceptance statement (`consent`), a PNG signature (size-limited, image-validated) where a signature applies, and the account's authenticator code when 2FA is on (`stepUp`, 401 `{totp:true}`); the portal records decided_by / name / IP / time and the event ("(mobile app)" on FSR events). Expired offers are refused server-side (409) whatever the client shows. | portal_customer.php, app/fsr.php `fsr_customer_decide` |
| CS-40 | **Uploads.** Images are re-encoded (EXIF dropped, ≤ 1600 px) before the portal's `tk_store_uploads()` allow-list (extension, 20 MB, 10 per post) applies; nothing is written outside the portal's storage. | `guardUploads()` |
| CS-41 | **Sessions and devices.** Same JWT 15 min / rotating refresh with reuse detection, 7 days in a browser, 30 on a phone; the app-side token store is Keychain / Keystore in the Capacitor build; devices listed and revocable by the customer (own devices only) and by administrators; `session_epoch` honoured (Sign out everywhere). Rate limits: auth 10/min per IP, 300/min per user, decisions 60/min. | lib/jwt.php, routes |
| CS-42 | **Client hardening.** CSP in the shell (`script-src 'self' cdnjs`, `object-src 'none'`), no inline scripts, `no-store`, service worker never caches the API; mock mode is a client-only demo and is stripped from store builds; the Capacitor config limits navigation to goldensas.com. | mobile-customer/index.html, sw.js, docs-R68/capacitor-customer |

Decisions 31/10 (Nikos): **D-8 applied** — offer decisions from the app require 2FA on the customer account (`PortalCustomer::offerNeeds2fa()`, setting `api_customer_offer_2fa`, default on; 403 `needs_2fa` with the instruction to enable it under Account; the app shows the notice instead of the buttons). **D-9 applied** — `fsr_render_pdf()` prints the stored signature PNGs (sp_files `fsr_sign`: engineer's `golden_sign_id`, customer's `customer_sign_id`, the latter only once accepted) inside the two acceptance boxes, 48 × 13 mm above the name / time / IP line; the customer remark then moves to its own block. Remaining: D-10 push producer for the four customer events (report submitted, document submitted, offer sent, ticket answered) into `mob_push_queue`; D-11 SRI hashes / bundled pdf.js in the store build (as D-6/CS-07).
