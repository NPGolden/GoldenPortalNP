## 1. Contacts (menu › Commercial › Contacts — Golden A/S staff only; owners never see it)

A contact is a person: **full name, position, category** (Owner, Owner's representative, Management company, Captain, Chief engineer, ETO, Crew, Yard, Class society, Supplier, Consultant / designer, Other), **customer** (a customer of the portal) and/or **company** (a yard, class society or supplier that is not a customer), e-mail, phone, mobile, an optional link to the person's **portal account**, **birthday** (with the year or day-and-month only), **name day** (day and month), **interests** (free text) and active / inactive.

- **Vessels**: every contact is linked to any number of vessels with the **role on that vessel** (Captain, Owner's rep, Chief engineer…) and one ★ primary vessel. The edit form lists the vessels grouped by customer with a filter box; the contact page has *Link / Unlink*. Each **vessel page** (overview) shows its contacts with role, category, reach, birthday and name day — marked *Internal*.
- **Notes**: a dated, signed note thread on every contact (add on the page or as the "first note" when creating; the author or an administrator can delete). A note can also come in through the Excel import.
- **Dates to remember**: the contact page shows the next birthday (with the age the person turns) and the next name day, in days. The Contacts page opens with counters (contacts, companies, vessels covered, **birthdays in 30 days, name days in 30 days**) and a **Celebrations** column listing every birthday 🎂 and name day 🎉 of the next 30 days, soonest first.
- **Filters**: search (name, company, e-mail, phone, position, interests), customer (incl. "no customer"), vessel (incl. "no vessel"), category, *coming up* (birthdays / name days in 30 days), active / inactive / all; paged 50 per page.
- Administrators can delete a contact (with its notes and vessel links); staff can create and edit.

## 2. Excel import of contacts (Settings › Import from Excel › Contacts, or ⤒ on the Contacts page)

Template `GAS-contacts-import-template.xlsx` (sheet *Contacts* + *How to*): **Full name · Company · Category · Position · Email · Phone · Mobile · Vessels · Birthday · Name day · Interests · Notes**.

- *Company* = a customer name of the portal (links the contact to that customer) or any other company.
- *Vessels* = vessel names as in the portal separated by `;`, with the role in brackets: `MY GY-85-02 (Owner's rep); MY-GY-62-01`. Spelling is forgiving (`MY GY-85-02`, `MY-GY-85-02`, `gy8502` and the IMO all match); the vessel must already exist — unknown names are listed under *Warnings* and skipped, the contact is still imported.
- *Birthday* `15.03.1975` or `15.03` (no year); *Name day* `06.12`; Excel dates, `yyyy-mm-dd` and `15 March` also work. Category in English or the portal language.
- Matching by **e-mail**, else by **name + company** (or name alone when it is unique). Existing contacts are updated: filled cells overwrite, blank cells keep. A note is added once (not repeated on re-import). *Check only* first; the result counts rows / contacts added / updated / vessel links / notes, lists skipped rows (no name, invalid e-mail) and warnings (unknown category → Other, unknown vessel, date not understood).

## 3. Excel import of portal accounts (Settings › Import from Excel › Portal accounts — administrators)

Template `GAS-accounts-import-template.xlsx` (sheet *Accounts* + *How to*): **Full name · Email · Role · Customer · Golden A/S role · Discipline · Manager · Language · Password · 2FA required · Active**.

- *Email* identifies the account: existing → updated, new → created (*Full name* required). *Role* customer / staff / admin (default customer); *Customer* required for customer accounts and created if missing. *Golden A/S role* is created if unknown; an unknown *Discipline* or *Manager* is reported. *Language* en / el / it / uk / bg (also "Greek", "gr"…). *2FA required* / *Active* yes / no, blank keeps (new accounts: 2FA required, active).
- *Password*: at least 10 characters; blank keeps the current one. A **new account without a password gets a generated one** (`FDR4R-LVmR-WQzR!` style), listed **once** in the result page — copy them there and hand them over securely; the *check only* run shows them masked.
- Skipped rows: invalid e-mail, missing name for a new account, unknown role, short password, customer account without customer. Filled cells overwrite, blank cells keep.

## 12. v1.18.1 — GAS-CP-R18-002 (notifications)

Database step `install/migrate_cp_r18_notifications.sql` (two tables: `notifications`, `nf_cursor`; the cursors start at the *current* end of every event table, so nothing from before the step is announced). Then replace the files and Ctrl+F5.

**What the user sees**

- A **bell** in the top bar with the number of unseen entries; it opens a drop-down with the eight newest unseen entries (group pill, what happened, the object, who did it, how long ago), *Mark all as seen* and *All notifications*. No JavaScript — it is a plain `<details>` element, so it works on every browser and in both themes.
- A **gold dot** on each menu group (Fleet · Work · Commercial · Library) that has unseen entries, next to the existing "waiting for you" badges.
- A **Notifications page** (`?p=notifications`) with tabs *All · Fleet · Work · Commercial · Library* (each with its unseen count), an *All / Unseen* switch, 40 entries per page, *Open* (goes to the ticket / offer / sub-project tab… and marks the entry as seen), *Mark as seen* per entry, *Mark {group} as seen* and *Mark all as seen*. Seen entries stay listed for 90 days, greyed with the time they were seen.

**Where the entries come from** — nothing new is written when something happens; a sweep (at most once a minute, on any page load, under a database lock so two visitors never run it twice) reads the history tables the modules already keep, past a per-source cursor, and turns each new row into entries:

| Group | Source | Announced | Not announced |
|---|---|---|---|
| Work | tickets: history + comments | created, assigned, status changes, owner replied, work-order / report linked, new comment | *edited*; internal comments go to Golden A/S only |
| Work | work orders | submitted, approved, rejected, started, done, cancelled, reopened, note | *saved*; drafts go to Golden A/S only |
| Work | service reports | submitted, accepted, disputed (sent back), reopened | *created*, *saved*; drafts go to Golden A/S only |
| Work | timesheets (staff only) | submitted, approved, rejected, invoiced, un-invoiced, withdrawn | *created*, *saved* |
| Commercial | offers | sent, re-sent, approved, rejected, imported, every status change | *edited*; amounts in the note are masked for roles without financial visibility (R18-001) |
| Commercial | owner approvals | new document submitted, comment, approved, approved with comments, rejected, new revision | drafts go to Golden A/S only |
| Commercial | contact notes (administrators) | new note | — |
| Fleet | class submittals, drawing requests | new rows — several added at once are folded into one entry ("3 drawing requests added") | — |
| Fleet | weekly notes, sub-project comments | new note / comment | internal ones go to Golden A/S only |
| Library | documents | new document | — |

**Who receives them** — for anything under a project: the project manager, every administrator, and (when it is visible to the owner) the active users of the project's customer; plus the people on the record itself (ticket assignee and creator, work-order requester, report author, timesheet owner and approver). The person who made the change never gets an entry about it. One unseen entry per object per person: a second change on the same ticket replaces the earlier unseen entry (the newest event wins), so a busy ticket is one line, not ten.
